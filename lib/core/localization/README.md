# Localization (i18n)

This project uses Flutter's `gen_l10n` pipeline with ARB files, plus an optional **remote override** layer for updating translations without shipping a new app build.

## Folder layout

- `lib/core/l10n/`
  - `app_<locale>.arb`: source translation files (e.g. `app_en.arb`).
  - `app_localizations*.dart`: generated by Flutter (`gen_l10n`) from the ARB files.
  - `untranslated.txt`: generated list of missing translations (see `l10n.yaml`).
- `lib/core/localization/`
  - `hybrid_localizations_delegate.dart`: loads Flutter-generated localizations, then optionally overrides strings from a remote ARB (with SharedPreferences caching).
  - `remote_app_localizations.dart`: generated wrapper used by the hybrid delegate.

## Add / edit a localized string

1. Edit the template ARB: `lib/core/l10n/app_en.arb`.
2. If you support other locales, add/edit the same key in `lib/core/l10n/app_<locale>.arb`.
3. Re-generate Flutter localizations:
   - `flutter gen-l10n`

## Add a new locale

1. Create `lib/core/l10n/app_<newLocale>.arb` (for example `app_ar.arb`).
2. Run `flutter gen-l10n`.
3. Ensure the app includes:
   - `localizationsDelegates: AppLocalizations.localizationsDelegates`
   - `supportedLocales: AppLocalizations.supportedLocales`

## Remote overrides (optional)

`HybridLocalizationsDelegate` fetches `app_<locale>.arb` from a remote endpoint and overlays those values on top of the generated `AppLocalizations` fallback. If the fetch fails, it will use the cached ARB (if available) or fall back to the bundled strings.

When ARB keys change, regenerate the override wrapper:

- `dart run tool/generate_remote_app_localizations.dart`
